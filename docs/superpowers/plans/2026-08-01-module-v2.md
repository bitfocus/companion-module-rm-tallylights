# Companion Module v2.0.0 — Feedbacks and Variables — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the module four feedbacks and five variables, driven by a WebSocket to the master rather than by polling, and make it fit to publish on the Bitfocus registry.

**Architecture:** One persistent WebSocket to the master's `/ws`, which pushes a full state snapshot on connect and on every change. A pure reducer (`state.ts`) holds the latest snapshot; feedbacks and variables read from it. `socket.ts` owns the connection and nothing else. The logic that can be wrong lives in pure functions with unit tests; the parts that need a real device are verified on one.

**Tech Stack:** TypeScript ~6.0.3, `@companion-module/base` 2.0.4, Node ^22.20 (its global `WebSocket` — no new dependency), Yarn 4, Vitest.

## Global Constraints

- **Two documents govern this work.** The module spec is `docs/superpowers/specs/2026-08-01-module-v2-feedbacks-design.md`. The **wire protocol is owned by the firmware spec**, `~/Documents/Arduino/RMTallyLights/RMTallyLights_Master/docs/superpowers/specs/2026-08-01-firmware-v1.3.0-websocket-push-design.md` §3. Where this plan and either document disagree, the spec wins — stop and say so.
- **Runtime dependencies stay at exactly one** (`@companion-module/base`). Adding any npm runtime dependency fails this release. Dev dependencies are unchanged too — everything here uses what is already installed.
- **v2.0.0 is the first public release.** v1.0.0 was never published. The module goes to the Bitfocus registry from this branch, so user-facing copy counts.
- **Do not change any action.** Action ids, option ids, behaviour and the HTTP endpoints they call are all v1 surface and stay exactly as they are. This release only adds.
- **Commands keep going over HTTP.** The master ignores inbound WebSocket frames by design (firmware spec §3.4). Never send on the socket.
- **The master is at `192.168.0.76`** running firmware v1.3.0, and `/ws` is live. Tasks may use it read-only for reference; only Task 8 drives it.
- **Verified API shapes** — these were read from `node_modules/@companion-module/base/dist/module-api/` and are not guesses. Getting them wrong is how v1 lost time:
  - `InstanceTypes['feedbacks']` entries are `{ type: 'boolean' | 'value' | 'advanced'; options: TOptions }` — the `type` field is part of the _schema_, not just the definition (`base.d.ts:34-40`, `feedback.d.ts:7-10`).
  - `InstanceTypes['variables']` is a flat `CompanionVariableValues` — `{ [id: string]: JsonValue | undefined }` (`variable.d.ts:17-19`).
  - `setVariableDefinitions()` takes a **keyed object** whose values are `{ name: string }`. It is **not** an array and there is **no** `variableId` field (`variable.d.ts:5-13`).
  - A boolean feedback definition needs `type: 'boolean'`, `name`, `defaultStyle`, `options` (an array of input fields) and `callback` (`feedback.d.ts:78-123`).
  - A preset's feedback entry is `{ feedbackId, options, style }` and **`style` is required** for a boolean feedback (`preset/definition.d.ts`, `CompanionPresetFeedback`).
  - `checkFeedbacks(id, ...ids)` requires at least one id (`base.d.ts:135`).
- **Commit messages:** conventional-commit prefix, imperative mood, ending with the trailer `Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>`. A `lint-staged` hook runs prettier on commit, so committed files may come back reformatted — that is expected, not a failure.
- **Commands:** `yarn test` (vitest run), `yarn lint`, `yarn build`. All three must pass before any commit.
- **Baseline:** `main` at `3eeda68`. Rollback is `git checkout v1.0.0`, with no external consequence — nothing is published yet.

  - `isOnAir(state: ModuleState): boolean`

**Context you need:**

A snapshot's shape is fixed by the firmware and already deployed. Every frame is:

```json
{
	"type": "state",
	"onair": "onair",
	"live": 2,
	"preview": 1,
	"cameras": [
		{ "id": 1, "mode": "preview" },
		{ "id": 2, "mode": "live" }
	]
}
```

`cameras` contains only cameras configured on the master, so an id can be
missing entirely. `live` and `preview` are `0` when nothing holds that role,
and the firmware guarantees they name a camera that is actually present in
`cameras` with that mode — the module reconciles nothing.

`hasUnknownCamera` exists for one purpose: the module maps camera id to name
from a list it fetched over HTTP, and that list goes stale when a camera is
added on the master. When a snapshot mentions an id the module has never heard
of, Task 5 re-fetches the list.

```ts
/**
 * The module's view of the master, and the pure functions that read it.
 *
 * No I/O and no Companion imports live here on purpose: this is the part of
 * the module whose logic can be wrong, so it is the part that is unit tested.
 */

export type CameraMode = 'live' | 'preview' | 'idle' | 'off'

export interface CameraState {
	id: number
	mode: CameraMode
}

/**
 * One `state` frame from the master's /ws. Shape is owned by the firmware spec
 * (2026-08-01-firmware-v1.3.0-websocket-push-design.md, section 3.2).
 *
 * `cameras` holds only cameras configured on the master, so an id can be
 * absent. `live` and `preview` are 0 for "none", and the firmware derives them
 * from the same list, so they can never name a camera missing from `cameras`.
 */
export interface StateSnapshot {
	onair: 'onair' | 'offair'
	live: number
	preview: number
	cameras: CameraState[]
}

export interface ModuleState {
	connected: boolean
	snapshot: StateSnapshot | null
}

export const initialState: ModuleState = { connected: false, snapshot: null }

/** Replaces the whole view. Snapshots are complete, so there is nothing to merge. */
export function applySnapshot(state: ModuleState, snapshot: StateSnapshot): ModuleState {
	return { ...state, snapshot }
}

/**
 * The last snapshot is deliberately kept when the socket drops. A stale tally
 * is more useful to an operator than a blank one, and the `connected` feedback
 * is what reports the connection itself.
 */
export function setConnected(state: ModuleState, connected: boolean): ModuleState {
	return { ...state, connected }
}

export function cameraMode(state: ModuleState, camId: number): CameraMode | null {
	const camera = state.snapshot?.cameras.find((c) => c.id === camId)
	return camera ? camera.mode : null
}

export function isLive(state: ModuleState, camId: number): boolean {
	return cameraMode(state, camId) === 'live'
}

export function isPreview(state: ModuleState, camId: number): boolean {
	return cameraMode(state, camId) === 'preview'
}

export function isOnAir(state: ModuleState): boolean {
	return state.snapshot?.onair === 'onair'
}

/**
 * True when the master reports a camera the module has no name for — which
 * means its cached camera list is stale and should be re-fetched.
 */
export function hasUnknownCamera(state: ModuleState, knownIds: number[]): boolean {
	if (!state.snapshot) return false
	return state.snapshot.cameras.some((c) => !knownIds.includes(c.id))
}
```

```ts
import type { CameraMode, CameraState, StateSnapshot } from './state.js'

export const RECONNECT_MIN_MS = 1000
export const RECONNECT_MAX_MS = 30000

const MODES: CameraMode[] = ['live', 'preview', 'idle', 'off']

/**
 * Validates one text frame against the firmware's protocol
 * (2026-08-01-firmware-v1.3.0-websocket-push-design.md, section 3.2).
 *
 * NEVER THROWS. Returns null for anything unusable, which the caller logs and
 * discards. Because snapshots are complete, discarding a bad frame costs
 * nothing — the next good one restores correctness with no reconciliation.
 *
 * Unknown extra fields are ignored rather than rejected, so the firmware can
 * add one without breaking a module that predates it.
 */
export function parseStateFrame(raw: unknown): StateSnapshot | null {
	if (typeof raw !== 'string') return null

	let parsed: unknown
	try {
		parsed = JSON.parse(raw)
	} catch {
		return null
	}

	// JSON.parse('null') succeeds, so this guard is load-bearing, not defensive
	// noise: without it the property reads below throw.
	if (typeof parsed !== 'object' || parsed === null) return null

	const frame = parsed as Record<string, unknown>
	if (frame.type !== 'state') return null

	const onair = frame.onair
	if (onair !== 'onair' && onair !== 'offair') return null

	const live = frame.live
	const preview = frame.preview
	if (!Number.isInteger(live) || !Number.isInteger(preview)) return null

	if (!Array.isArray(frame.cameras)) return null

	const cameras: CameraState[] = []
	for (const entry of frame.cameras) {
		if (typeof entry !== 'object' || entry === null) return null
		const { id, mode } = entry as Record<string, unknown>
		if (!Number.isInteger(id)) return null
		if (typeof mode !== 'string' || !MODES.includes(mode as CameraMode)) return null
		cameras.push({ id: id as number, mode: mode as CameraMode })
	}

	return { onair, live: live as number, preview: preview as number, cameras }
}

export interface StateSocketHandlers {
	onSnapshot: (snapshot: StateSnapshot) => void
	onConnected: (connected: boolean) => void
	log: (level: 'debug' | 'info' | 'warn', message: string) => void
}

/**
 * Owns one connection to the master's /ws and nothing else.
 *
 * The socket is receive-only: the master ignores inbound frames by design
 * (firmware spec section 3.4) and commands continue to go over HTTP.
 */
export class StateSocket {
	private socket: WebSocket | null = null
	private retryMs = RECONNECT_MIN_MS
	private timer: ReturnType<typeof setTimeout> | null = null
	private stopped = false

	constructor(
		private readonly url: string,
		private readonly handlers: StateSocketHandlers,
	) {}

	start(): void {
		this.stopped = false
		this.open()
	}

	/**
	 * Companion destroys and recreates an instance on every config change, so a
	 * leaked socket or timer per edit is a real leak in a long-running process.
	 */
	stop(): void {
		this.stopped = true
		if (this.timer !== null) {
			clearTimeout(this.timer)
			this.timer = null
		}
		if (this.socket) {
			// Detach first: close() fires onclose, which would otherwise schedule a
			// reconnect for a socket we are deliberately discarding.
			this.socket.onopen = null
			this.socket.onmessage = null
			this.socket.onclose = null
			this.socket.onerror = null
			try {
				this.socket.close()
			} catch {
				// Already closing or never opened; nothing to do.
			}
			this.socket = null
		}
		this.handlers.onConnected(false)
	}

	private open(): void {
		if (this.stopped) return

		let socket: WebSocket
		try {
			socket = new WebSocket(this.url)
		} catch (e) {
			// An unparseable URL throws synchronously; without this the reconnect
			// chain would end here and the module would go permanently silent.
			this.handlers.log('warn', `Could not open ${this.url}: ${String(e)}`)
			this.scheduleReconnect()
			return
		}
		this.socket = socket

		socket.onopen = () => {
			this.handlers.log('debug', `State socket open: ${this.url}`)
			this.handlers.onConnected(true)
		}

		socket.onmessage = (event: MessageEvent) => {
			const snapshot = parseStateFrame(event.data)
			if (!snapshot) {
				this.handlers.log('debug', 'Discarded an unrecognised frame from the master')
				return
			}
			// Reset the backoff on a received frame rather than on open: a master at
			// its client limit accepts and then drops, and resetting on open alone
			// would spin at the minimum interval forever.
			this.retryMs = RECONNECT_MIN_MS
			this.handlers.onSnapshot(snapshot)
		}

		socket.onerror = () => {
			// Always followed by onclose, which owns the reconnect. Logged only so a
			// failed handshake is not silent.
			this.handlers.log('debug', 'State socket error')
		}

		socket.onclose = () => {
			this.socket = null
			this.handlers.onConnected(false)
			this.scheduleReconnect()
		}
	}

	private scheduleReconnect(): void {
		if (this.stopped || this.timer !== null) return
		const delay = this.retryMs
		this.timer = setTimeout(() => {
			this.timer = null
			this.open()
		}, delay)
		this.retryMs = Math.min(this.retryMs * 2, RECONNECT_MAX_MS)
	}
}
```

```ts
import { isOnAir, type ModuleState } from './state.js'
import type { Camera } from './cameras.js'

export type VariablesSchema = {
	live_cam: string
	preview_cam: string
	live_cam_name: string
	preview_cam_name: string
	onair: string
}

/**
 * Keyed by variable id, each entry just a display name.
 *
 * This is the shape setVariableDefinitions() expects in
 * @companion-module/base 2.x -- an object, not an array, and with no
 * variableId field (see dist/module-api/variable.d.ts).
 */
export const VARIABLE_DEFINITIONS: Record<keyof VariablesSchema, { name: string }> = {
	live_cam: { name: 'Live camera number' },
	preview_cam: { name: 'Preview camera number' },
	live_cam_name: { name: 'Live camera name' },
	preview_cam_name: { name: 'Preview camera name' },
	onair: { name: 'On Air state' },
}

/** Empty string rather than a placeholder: nothing live should render as nothing. */
function nameFor(camId: number, cameras: Camera[]): string {
	if (camId === 0) return ''
	return cameras.find((c) => c.id === camId)?.name ?? ''
}

/**
 * Values are strings throughout, including the camera numbers, so a button
 * label shows `0` rather than an empty cell when nothing is live.
 */
export function variableValues(state: ModuleState, cameras: Camera[]): VariablesSchema {
	const live = state.snapshot?.live ?? 0
	const preview = state.snapshot?.preview ?? 0

	return {
		live_cam: String(live),
		preview_cam: String(preview),
		live_cam_name: nameFor(live, cameras),
		preview_cam_name: nameFor(preview, cameras),
		onair: isOnAir(state) ? 'onair' : 'offair',
	}
}
```

```ts
import { cameraChoices, resolveCam, MANUAL, UNSET, type Choice } from './camera-picker.js'
import { MIN_CAM, MAX_CAM } from './api.js'
import { isLive, isPreview, isOnAir } from './state.js'
import type ModuleInstance from './main.js'

const WHITE = combineRgb(255, 255, 255)
const RED = combineRgb(200, 0, 0)
const GREEN = combineRgb(0, 150, 0)
const AMBER = combineRgb(180, 120, 0)

/**
 * A feedback schema entry carries both the feedback's type and its options --
 * the type is part of the schema, not only of the definition. See
 * @companion-module/base dist/module-api/base.d.ts and feedback.d.ts.
 */
export type FeedbacksSchema = {
	camera_live: { type: 'boolean'; options: { cam: string; cam_manual: number } }
	camera_preview: { type: 'boolean'; options: { cam: string; cam_manual: number } }
	onair: { type: 'boolean'; options: Record<string, never> }
	connected: { type: 'boolean'; options: Record<string, never> }
}

/**
 * The same dropdown-plus-manual-entry pair the actions use, built from the
 * shared camera picker rather than reimplemented -- the picker's digit-only
 * guard exists because a blank dropdown once resolved to camera 0 and sent a
 * real command, and a second control is how that returns.
 */
export function feedbackCameraOptions(choices: Choice[]): SomeCompanionFeedbackInputField<'cam' | 'cam_manual'>[] {
	return [
		{
			id: 'cam',
			type: 'dropdown',
			label: 'Camera',
			// Never a real camera: an unconfigured feedback must match nothing
			// rather than silently track camera 1.
			default: UNSET,
			choices,
			// Required so the manual field's isVisibleExpression may reference this
			// field, and it stops the picker being turned into an arbitrary
			// expression -- the only route by which blank or non-digit text could
			// reach resolveCam.
			disableAutoExpression: true,
		},
		{
			id: 'cam_manual',
			type: 'number',
			label: 'Camera (manual)',
			default: 1,
			min: MIN_CAM,
			max: MAX_CAM,
			// base 2.x has no callback-style isVisible; visibility is an expression
			// string evaluated in the UI.
			isVisibleExpression: `$(options:${'cam'}) == '${MANUAL}'`,
		},
	]
}

export function UpdateFeedbacks(self: ModuleInstance): void {
	const camChoices = cameraChoices(self.getCameras(), false)

	self.setFeedbackDefinitions({
		camera_live: {
			type: 'boolean',
			name: 'Camera is Live',
			description: 'True while the master reports this camera as live.',
			defaultStyle: { bgcolor: RED, color: WHITE },
			options: feedbackCameraOptions(camChoices),
			callback: (feedback) => {
				const cam = resolveCam(feedback.options.cam, feedback.options.cam_manual, false)
				if (cam === null) return false
				return isLive(self.getState(), cam)
			},
		},

		camera_preview: {
			type: 'boolean',
			name: 'Camera is Preview',
			description: 'True while the master reports this camera as preview.',
			defaultStyle: { bgcolor: GREEN, color: WHITE },
			options: feedbackCameraOptions(camChoices),
			callback: (feedback) => {
				const cam = resolveCam(feedback.options.cam, feedback.options.cam_manual, false)
				if (cam === null) return false
				return isPreview(self.getState(), cam)
			},
		},

		onair: {
			type: 'boolean',
			name: 'On Air is On',
			description: 'True while the On Air light is on.',
			defaultStyle: { bgcolor: RED, color: WHITE },
			options: [],
			callback: () => isOnAir(self.getState()),
		},

		connected: {
			type: 'boolean',
			name: 'Master is Connected',
			// Deliberately not affected by whether the last action succeeded: an
			// action failing means one request failed, the socket dropping means the
			// master is gone, and conflating them makes the indicator flicker
			// exactly when a stable answer matters most.
			description: 'True while the state socket to the master is open.',
			defaultStyle: { bgcolor: AMBER, color: WHITE },
			options: [],
			callback: () => self.getState().connected,
		},
	})
}
```

```ts
			},
			log: (level, message) => this.log(level, message),
		})
		this.socket.start()
	}

	private stopSocket(): void {
		if (this.socket) {
			this.socket.stop()
			this.socket = null
		}
	}

	/**
	 * Re-reads the camera list after the master reports an id we do not know,
	 * then rebuilds everything whose labels depend on it.
	 */
	private async refreshCameras(): Promise<void> {
		const cameras = await fetchCameras(this.getApiTarget())
		if (cameras.length === 0) return
		this.cameras = cameras
		this.updateActions()
		this.updateFeedbacks()
		this.updatePresets()
		this.pushState()
	}

	/** Pushes the current state into Companion. Cheap enough to call on every frame. */
	private pushState(): void {
		this.checkFeedbacks('camera_live', 'camera_preview', 'onair', 'connected')
		this.setVariableValues(variableValues(this.state, this.cameras))
	}

	updateFeedbacks(): void {
		UpdateFeedbacks(this)
	}

	updateVariables(): void {
		UpdateVariables(this)
	}
```
